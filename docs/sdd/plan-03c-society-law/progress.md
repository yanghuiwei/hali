- **控制器自查（实算，不是推演）**：用 Python 逐值核对 spec 内所有数字，
  发现并修掉 **3 个设计期缺陷**：

  | # | 缺陷 | 证据 | 修法 |
  | --- | --- | --- | --- |
  | ① | 家族财富初稿「豪富 5000–50000 加隆」是**拍数**，且稀释论证算错 | 初稿用「未稀释总额」论证「不稀释则 1023 年生活费」——实测**独子才 319.6 年、4 子均分只有 79.9 年**（我把总额当年生活费，且忽略了均分本身已在稀释） | 改以「中位家庭年收入（168 加隆）倍数」定义档位；巨富上限收敛到 **50385**；采用 30% 税 + 4 份均分 ⇒ 玩家得 **8817 加隆（55.9 年）** |
  | ② | 法律风险**只有累积没有衰减** ⇒ 不可玩 | 实算：从 heat=3 起每月 +1 ⇒ **第 8 月必定被抓，且中间无任何补救手段**。这不是「严格」而是「死亡螺旋」 | 加 `HEAT_DECAY=1`（自然冷却）+ `pay_fine` 通道（1 加隆 = 1 点 heat，25 加隆 = 1.79 月薪可清 heat=10）；并钉死**「先衰减后判定」**顺序 |
  | ③ | **`player.reputation` 全仓库无写入方** | `grep` 只有 `player_state.gd:23`（声明）+ 3 处读取（`prompt_builder.gd:92`、`panel_formatter.gd:47/163`）⇒ 恒为 0，拿它当发现率修正 = **死路径**（同 03b 缺陷⑧ `world_vars["location_tag"]`） | **从设计中删掉该修正项**；司法偏见改用 `birth_identity_id` / `bloodline` / `standing` / `illegal_affiliation` 四个**有写入方**的字段 |

- **实况核对（spec 定稿前对每个引用参数跑 `grep` 确认写入方）** —— 这是 03b 缺陷⑧ 元教训
  第一次**在设计期**生效，共抓到 4 处：

  | 核对项 | 结论 | 处置 |
  | --- | --- | --- |
  | `world.economy["smuggling_heat"]` | **累计**递增（`state_ops.gd:293`），非月度分桶 | 改为「读累计 + 自我差分」，存 `law["_smuggle_seen"]` |

  | `era_overrides` 键 | 初稿写 `"founding"`，实际 id 是 **`hogwarts_founding`** | 改用真实 id，并写成校验要求 |
  | `birth_identities` 特权类 | 初稿写 `pureblood_aristocrat`，实际是 **`noble_pureblood`** | 改用真实 id 列表 |
